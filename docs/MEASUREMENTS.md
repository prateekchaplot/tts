## Method

- The real application (`create_app`) runs in a background uvicorn thread with `TTS_FAULT=none`, rate 1.0, and volume 1.0.
- A generation is driven entirely through the HTTP API. Timestamps use `time.perf_counter()`: submit = POST send to the 202 response; started = the first `progress` event; first sentence = the first `progress` event with `sentenceIndex >= 1`; total = POST send to the `succeeded` event; audio ready = POST send to the completed audio download (the point where the UI can play).
- Per-sentence latency is the gap between consecutive completion events; the first sentence is reported separately because it includes queueing and model work.
- One warm-up generation per voice loads the model and is excluded.
- Each voice runs the short text once, the target text 3 times, and the long text once.
- Word-start deviation: the WAV is split into RMS frames of 10 ms rounded to whole samples (220 samples, 9.977 ms, at 22,050 Hz) and the speech threshold is 4% of the clip's 99th-percentile frame RMS (floor 0.002). Frame positions are converted with the exact frame duration, not a nominal 10 ms, so a long file cannot accumulate a scale error. A word is measurable when it is aligned, at least 100 ms have passed since the previous word, and the 100 ms before its reported start is silent. The first frame above the threshold between 60 ms before and 350 ms after the reported start is the acoustic onset. Deviation = onset minus reported start (positive means the highlight leads the voice).
- Connected speech rarely leaves a silent gap between neighbouring words, so most measurable words start a sentence or follow a pause. Sentence-initial words (the previous token ends a sentence) are also reported separately. Words without a silence gap are counted as excluded, never silently dropped.
- This is a signal-based proxy for audibility; the manual listening checklist below is the AC7 human spot-check.

On this Windows checkout the command runs from the repository root with `.venv\Scripts\python.exe`. The script seeds the measurement data directory from `.venv/tts-data/voices` when it is empty and never touches the user's `%LOCALAPPDATA%\tts` library.

## Notes and caveats

- Piper's duration predictor is stochastic (T1.2 measured about 1.73x instead of the nominal 2x at rate 0.5), so latency and duration vary run to run; medians are reported, not single samples.
- The onset detector needs a silent gap, so it measures words that start a sentence or follow a pause far more often than words inside a clause. Excluded words are counted in the table rather than hidden.
- Words whose phonemes do not reconcile are `aligned=false` with a zero-width span and are counted as unaligned, not as a measurement.
- Measurements are CPU-only and single-process, with the voice cache warm after the per-voice warm-up run. A busy machine shifts the latency columns.
- The tolerance verdict is signal-based, not a human judgement; the checklist above remains the AC7 manual step.
